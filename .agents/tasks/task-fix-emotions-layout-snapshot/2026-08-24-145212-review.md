# Emotion detection fix, canvas snapshot, and Bolivian poetry

This change fixes a broken emotion detection pipeline that always returned "happy" by adding the missing landmark model and a confidence threshold that falls back to "neutral" below 0.4. The camera layout switches from `object-cover` with restrictive max-heights to `object-contain` so faces aren't clipped. Snapshot mode now composites the photo, a gradient overlay, the emotion emoji, a poem, and a watermark into a single downloadable JPEG via canvas. All poems are replaced with culturally specific Bolivian Oriente poetry.

Watch for: the `emotionConfidence` variable is assigned identically in both branches of the threshold conditional (confirmed); the `getEmotionAccentColor` function at the bottom of FaceDetector.tsx is dead code (confirmed); long poems may overflow the canvas gradient region on low-resolution captures (likely).

**Verdict**: NEEDS_CHANGES

## High-level view

The detection pipeline now loads `faceLandmark68Net` and chains `.withFaceLandmarks()` before `.withFaceExpressions()`, giving the expression model the alignment data it needs. A 0.4 threshold gates the mapped emotion — anything below becomes "neutral" — but the confidence value stored alongside it doesn't reflect this fallback, creating a logical inconsistency in the label displayed over each face box.

The snapshot compositing is entirely client-side: a temporary `Image` loads the captured data-URL, draws onto a detached canvas, and layers gradient + text + watermark before resolving with a JPEG data-URL. The poem text layout doesn't bound its vertical extent, so long poems can overflow below the canvas on low-resolution frames.

The poems replacement is a complete content swap — same structure (7 emotions × 4 poems), same `getRandomPoem` API — with references to Oriente Boliviano geography, fauna, and cultural motifs.

## Detection pipeline: landmarks and confidence gating

Without landmark alignment, `faceExpressionNet` receives a poorly-registered face crop and produces near-uniform low-confidence scores across all classes; "happy" edged ahead by a tiny margin in most frames. Adding `.withFaceLandmarks()` provides the alignment data that fixes this.

The confidence threshold at 0.4 gates `emotionKey` correctly, but the code that stores the confidence value has a bug:

```typescript
const emotionConfidence = maxExpression[1] >= EXPRESSION_CONFIDENCE_THRESHOLD
  ? maxExpression[1]
  : maxExpression[1]; // ← identical in both branches
```

Both branches assign the raw `maxExpression[1]`, so `emotionConfidence` never reflects the override to "neutral". The bounding-box label uses `Math.round(maxExpression[1] * 100)%` directly, so users will see "😐 Neutral (25%)" where 25% was actually the confidence of some other expression that didn't meet the threshold.

## Canvas compositing: poem overflow risk

The poem text layout doesn't check whether lines exceed the available vertical space between `textStartY` and the canvas bottom. The poems are 3–4 phrases of prose each, which can produce 6–8 wrapped lines at `maxTextWidth = img.width * 0.8`. On a 720p capture this barely fits (text ends around y=711 within a 720px canvas). On a 320px-height capture, the math breaks: gradient starts at 192px, text starts around 280px, and 7 lines × 21px line-height = 147px → ends at 427px, well past the 320px bottom. A line-count cap or dynamic font reduction would prevent the overflow.

## Dead code: `getEmotionAccentColor`

An unexported, unreferenced function at the bottom of FaceDetector.tsx. Likely a leftover from an earlier iteration. Should be removed to avoid confusion.
